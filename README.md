# Team Memory

Общая Markdown-база задач и знаний команды. Агент читает материал, находит существующие
записи и предлагает изменения через PR. Опубликованная база — основная ветка удалённого
репозитория; merge выполняет человек.

## Быстрый старт

Требуется Python 3.10+ и Git. Из корня репозитория:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 scripts/validate.py
python3 scripts/validate.py --root tests/fixtures/demo
python3 scripts/search.py --root tests/fixtures/demo --kind task --open --all --json
```

Рабочая база изначально пустая. В `tests/fixtures/demo` — только вымышленные данные:
два проекта, общая система, участники с неоднозначными aliases, задачи и знания.
Они не попадают в обычный поиск. Для первой записи попросите агента сохранить описание
проекта и исходный запрос как `source`, затем создать нужные задачи и знания.

## Подключение агента

Канонический skill находится в `skills/team-memory/SKILL.md`. В `.agents/skills/team-memory`
лежит относительная символьная ссылка на него: второй копии инструкций нет. Откройте
этот репозиторий в новой сессии Codex и вызовите `$team-memory`. Codex поддерживает
репозиторные skills и ссылки на каталоги по [официальной документации](https://learn.chatgpt.com/docs/build-skills).
Если skill ещё не виден, перезапустите сессию; явное чтение указанного SKILL.md позволяет
проверить выполнение независимо от автоматического обнаружения.

Для GigaCode или другого harness передайте путь к этому же SKILL.md способом, который
поддерживает установленная версия. Team Memory не требует конкретной модели, входа или
CLI-флагов. GigaCode в среде разработки не установлен; его подключение здесь не проверено.

Примеры запросов:

- «Разбери это дейли по Team Memory, обнови задачи и знания, подготовь PR».
- «Добавь инструкцию по обновлению Relay; сначала найди существующую тему».
- «Покажи все открытые задачи Атласа с источниками».
- «Найди общие сведения о Relay, включая другие проекты».
- «Проверь базу на дубли и противоречия; пока ничего не исправляй».
- «Повторно обработай этот источник: добавилось уточнение».

Поиск и ответы не редактируют Markdown. Для строго неизменяемого файлового дерева
используется `--no-cache`; обычный поиск обновляет только игнорируемый каталог.

## Форматы и инструменты

Контракт: [records.md](skills/team-memory/references/records.md).
Шаблоны: [templates](skills/team-memory/templates). При копировании замените `replace-id`,
заголовок, описание, дату, относительные ссылки и содержание. UUID4 для задач, знаний
и источников: `python3 -c 'import uuid; print(uuid.uuid4())'`, затем добавьте префикс типа.
Проектам, участникам и системам назначайте постоянные читаемые ID. Не меняйте ID при
переименовании. Для первого запроса создайте `note`, чтобы у задач был источник.

```sh
python3 scripts/search.py Relay --json
python3 scripts/search.py --id task-atlas --root tests/fixtures/demo --json
python3 scripts/search.py --project Atlas --kind task --all --root tests/fixtures/demo
python3 scripts/search.py --system 'Relay API' --root tests/fixtures/demo --limit 5 --offset 5
python3 scripts/search.py --kind knowledge --knowledge-type how-to --all
python3 scripts/search.py --rebuild --all
python3 scripts/search.py --open --all --no-cache --json
python3 scripts/validate.py
```

Поиск выдаёт кандидатов с путями; для ответа агент читает записи целиком. `--all`
возвращает все совпадения. Без него смотрите `total` и `next_offset`, а не принимайте
первую порцию за весь результат. Одинаковые aliases разрешаются явным выбором ID.
Поиск лексический: смысловые дубли требуют агентского сопоставления и разных запросов.

Каталог `.team-memory/search.json` пересоздаётся из Markdown. Его можно удалить или
выполнить `--rebuild`: данные хранятся только в Markdown. Перед каждым поиском сверяются
байты файлов, включая изменения без коммита. Это линейное чтение базы, рассчитанное на v1.

## Совместная работа

[Git workflow](skills/team-memory/references/git-workflow.md) задаёт отдельную ветку
на запрос, повторную смысловую сверку с основной веткой и максимум три попытки.
[GitHub setup](docs/github-setup.md) содержит настройку приватного репозитория и защиты.
CI проверяет структуру и тесты без агента и секретов. Правильность фактов, смысловые дубли
и актуальность инструкций он не доказывает.

## Проверки и границы

[Сценарии](tests/scenarios/README.md) описывают отдельные проверки агентского поведения.
[Отчёт проверки](docs/verification.md) отделяет выполненные проверки от оставшихся.
Автосбор сообщений, фоновые runner, UI, векторный поиск и прямые LLM API не входят в v1.
Sourcery и USW не требуются. [Исходный план](docs/2026-10-19-team-memory-plan.md) сохранён
как историческое основание; отдельный исходный дизайн не был предоставлен.
