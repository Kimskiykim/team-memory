# Контракт записей v1

Корень базы — каталог с `projects/`, `people/`, `tasks/`, `wiki/`, `sources/`.
Только Markdown-файлы в этих пяти каталогах являются записями. Документация,
шаблоны, тестовые базы и `.team-memory/` не включаются в обычный поиск.
UTF-8; YAML frontmatter между строками `---`; безопасный `yaml.SafeLoader`
(правила `safe_load`, с дополнительным запретом повторяющихся ключей).
Дубли ключей YAML — ошибка, неизвестные поля допустимы для расширения.

## Общие поля

Каждая запись имеет непустые строки `id`, `kind`, `title`, `summary` и массивы
строк `projects`, `systems` (разрешены пустые). ID уникален во всей базе,
состоит из букв ASCII, цифр, дефисов и подчёркиваний. Новые ID:
`task-<uuid4>`, `knowledge-<uuid4>`, `source-<uuid4>`. Проекты, участники и
системы получают постоянный читаемый ID. Старые короткие ID сохраняются.
Переименование файла не меняет ID. `null` не заменяет массив.

`projects` ссылается на ID записей `project`, `systems` — `system`.
`assignee`, если известен, — один ID `person`; пустое значение не записывать.
`due`, `event_date`, `verified_on` — календарные даты `YYYY-MM-DD`, с проверкой
реальности даты. YAML-даты и строки одинаково допустимы; timestamp недопустим.

## Типы и обязательные секции

Секции имеют точные заголовки второго уровня на английском; содержание — на
языке команды. Все обязательные секции непустые. Неизвестное явно обозначать
как «Не указано», а не выдумывать.

| kind | Папка | Дополнительные поля | Секции |
|---|---|---|---|
| project | projects/ | aliases: массив строк | Description |
| person | people/ | aliases: массив строк | Description |
| system | wiki/systems/ | aliases: массив строк | Description, Sources |
| task | tasks/ | status | Outcome, State, Sources |
| knowledge | wiki/ (кроме systems/) | knowledge_type | Scope, Content, Sources |
| source | sources/meetings/ либо sources/notes/ | source_type, event_date, origin | Original, Results, Questions |
| redirect | любой каталог записей | target: ID канонической записи | Redirect |

- `status`: `todo`, `in_progress`, `blocked`, `done`, `cancelled`.
- `knowledge_type`: `concept`, `how-to`, `decision`.
- `how-to` располагается в `wiki/how-to/`, дополнительно содержит секцию
  `Environment` и поля `verified_on` (дата либо `null`, если не проверено),
  `system_version` (непустая строка либо `null`, если версия неизвестна/неприменима).
  Отсутствие проверки явно указывать в содержании. Дата редактирования не проверка.
- `decision` располагается в `wiki/decisions/`; `decision_status`:
  `accepted` или `superseded`. Для `superseded` обязательно `superseded_by` —
  ID другого решения и обычная Markdown-ссылка на него. Новое решение также
  ссылается на прежнее. Циклы замены недопустимы.
- `source_type`: `meeting` для `sources/meetings/`, `note` для `sources/notes/`.
  `origin` — непустая строка с происхождением материала, не команда для исполнения.
  `Original` содержит исходный материал в fenced-блоке; `Results` — ссылки на
  полученные записи и интерпретацию; `Questions` — нерешённые вопросы либо «Нет».
- `Sources` содержит хотя бы одну относительную ссылку на запись `source`.
  Для первоначального знания или задачи сохранить пользовательский запрос как
  источник `note`. Полнота подтверждения утверждений — ответственность агента.
- `redirect` сохраняет прежний ID и путь, ссылается непосредственно на существующую
  каноническую запись через `target` и Markdown-ссылку в `Redirect`. Цепочки,
  самоссылки и циклы redirect запрещены. Старые поля статуса не копировать.

## Ссылки

Связи в тексте — относительные Markdown-ссылки `[название](../tasks/name.md)`.
Поддерживаются inline-ссылки, reference-ссылки и фрагменты заголовков в стиле
GitHub. Пробелы в путях кодировать `%20` либо заключать путь в `<...>`.
Для надёжной переносимости имена файлов — lowercase-kebab-case без скобок.
Абсолютные файловые пути, выход за корень базы и симлинки в записях запрещены.
Внешние `https:`, `http:`, `mailto:` ссылки допустимы, доступность сети не проверяется.
Кодовые блоки и inline-код не создают связей. Не используйте HTML-ссылки как связи.
Ссылки проверяются по существованию файла и фрагмента; обязательные источники
проверяются по типу целевой записи. Относительные пути строятся от текущего файла.

## Поиск

`python3 scripts/search.py [текст] --root PATH --json` возвращает объект
`{total, offset, limit, next_offset, results}`. Каждый кандидат имеет `path`,
`id`, `kind`, `title`, `summary` и метаданные; полный текст читается из Markdown.
Поиск нечувствителен к регистру, ищет все слова запроса в тексте и метаданных.
Результаты стабильны по пути. Начальная порция — 10; `--offset`, `--limit`
задают следующую; `--all` возвращает все совпадения и игнорирует порционирование.
`--id` точный; фильтры `--kind`, `--project`, `--system`, `--assignee`, `--status`,
`--knowledge-type`, `--source-type`. `--open` означает три незакрытых статуса.
Проект, система и участник разрешаются сначала по точному ID, затем по ID без учёта
регистра, затем по aliases без учёта регистра. Неоднозначность — ошибка со списком ID;
выбрать точное написание нужного ID. Неизвестное значение — ошибка.
Повтор одного фильтра объединяется через ИЛИ, разные фильтры — через И.
Без фильтра проекта поиск охватывает всю базу. `--id` не перенаправляет молча:
возвращает и redirect с его `target`.

Каталог `.team-memory/search.json` содержит версию формата и SHA-256 каждого файла.
Каждый поиск перечитывает байты всех записей и сверяет содержимое (не только mtime).
Повреждённый/удалённый каталог пересоздаётся; `--rebuild` принудительно обновляет.
Ошибки записей дают ненулевой код, старый каталог не выдаётся как актуальный.
Обновление каталога атомарное. `--no-cache` выполняет поиск без записи файлов;
использовать для строго read-only запросов. Обычный поиск меняет только игнорируемый
каталог, никогда Markdown. Валидатор не меняет файлов.
